# WProxy 2.8.4 — New desktop Manager

## فارسی

WProxy کلاینت دسکتاپ برای کانفیگ و ساب خودت است؛ اکانت یا سرور VPN آماده همراهش نیست. این نسخه رابط جدید Manager را با زمینهٔ تیره، رنگ سبز، دکمهٔ دایره‌ای اتصال و کارت‌های وضعیت/مصرف ارائه می‌کند. بازطراحی ظاهر روی همان موتورهای اتصال و بک‌اند فعلی قرار گرفته است. این ریلیز اصلاحات اتصال و بازیابیِ قبلاً توسعه‌داده‌شده را هم نسبت به ریلیز 2.8.3 شامل می‌شود.

### چه فایلی بگیرم؟

| فایل | کاربرد |
| --- | --- |
| **WProxy-2.8.4-Setup.exe** | ویندوز ۱۰/۱۱ **x64**؛ برنامه، sing-box، Xray، Mihomo و Wintun همراهش هستند. Python یا دانلود جداگانهٔ موتور لازم نیست. |
| **WProxy-2.8.4-GitHub.zip** | سورس و نصب‌کنندهٔ لینوکس؛ پس از استخراج، وابستگی‌های توزیعت را طبق README نصب کن و دستور نصب را اجرا کن. |
| **WProxy-2.8.4-Plasma6.plasmoid** | فقط ویجت پنل KDE؛ برای کارکردن به بک‌اند نصب‌شدهٔ WProxy نیاز دارد. |
| **SHA256SUMS / Setup.exe.sha256** | بررسی هش فایل‌های دانلودشده. |

### از کجا شروع کنم؟

1. در ویندوز Setup را نصب کن و WProxy را از منوی برنامه‌ها باز کن. در لینوکس، از پوشهٔ ZIP استخراج‌شده دستور مناسب را بزن: `bash scripts/install.sh --desktop gnome` برای GNOME، `--desktop kde` برای Plasma 6 یا `--desktop none` برای Manager بدون افزونهٔ پنل. وابستگی‌های هر توزیع در README آمده‌اند.
2. ساب را در **Subscriptions** وارد کن. برای تک‌کانفیگ، **Servers → Add server** لینک، متن JSON/YAML و فایل می‌پذیرد. اصل کانفیگ محلی نگه داشته می‌شود و موتور سازگار براساس ویژگی‌های آن انتخاب می‌شود.
3. برای عبور معمول کل سیستم، **Routing → All traffic** را انتخاب کن. سپس در **Dashboard** دکمهٔ اتصال / **Quick connect** را بزن؛ برنامه از فرمان قبلی بررسی HTTPS و انتخاب سرور استفاده می‌کند. برای انتخاب دستی از **Connect** کنار سرور استفاده کن.
4. وقتی متصل هستی، **Switch** روی سرور دیگر اتصال را جابه‌جا می‌کند. قطع اتصال از دکمهٔ دایره‌ای Dashboard یا جزئیات سرور فعال انجام می‌شود.
5. سایت را با مرورگری که در فهرست bypass نیست باز کن. پینگ TCP فقط پاسخ‌دادن سرور را می‌سنجد و تضمین نمی‌کند YouTube یا همهٔ سایت‌ها کار کنند؛ خرابی سرور، اینترنت و قوانین Routing می‌توانند نتیجه را عوض کنند.

### داخل Manager چه داریم؟

- **Dashboard:** وضعیت واقعی تونل، سرور و موتور، زمان نشست، مصرف حافظه و نمودار ترافیک اندازه‌گیری‌شده.
- **Servers:** جست‌وجو، فیلتر منبع/موتور، مرتب‌سازی پینگ/نام، علاقه‌مندی‌ها، لیست/کارت، تست پینگ و جزئیات سرور.
- **Subscriptions:** افزودن و آپدیت تکی/جمعی ساب‌ها، تعداد سرورها، مصرف و تاریخ انقضا در صورت ارائهٔ سرویس‌دهنده.
- **Routing:** در **All traffic** ترافیک از VPN می‌رود؛ در **Only selected** فقط برنامه‌ها/سایت‌های انتخاب‌شده از VPN می‌روند؛ در **Bypass selected** موارد انتخاب‌شده مستقیم می‌مانند. برنامه را از فهرست برنامه‌های نصب‌شده/درحال‌اجرا انتخاب کن یا فایل اجرایی را معرفی کن. حالت Only selected باید حداقل یک مورد داشته باشد.
- **Settings:** تم روشن/تیره/سیستم، کنترل انیمیشن، آپدیت خودکار، نمایش موتورهای نصب‌شده و بررسی سلامت اتصال. گزینهٔ مجوز یک‌باره فقط در لینوکس نمایش داده می‌شود؛ مجوز محدود WProxy ذخیره می‌شود و رمز sudo ذخیره نمی‌شود. تغییر مسیر TUN در ویندوز درخواست UAC سیستم دارد.
- **Ctrl+K:** جست‌وجوی صفحه‌ها، سرورها و فرمان‌ها. فونت‌ها و لوگو محلی‌اند؛ کاهش حرکت سیستم رعایت می‌شود و خواندن دوره‌ای وضعیت هنگام مخفی‌بودن پنجره متوقف می‌شود.

تغییر Routing در لینوکس از مسیر قبلی اعمال روی تونل فعال استفاده می‌کند؛ در ویندوز بعد از تغییر، دوباره وصل شو. نمونه: برای عبور فقط مرورگر، **Only selected** را بزن و مرورگر را اضافه کن. برای مستقیم‌ماندن برنامهٔ پشتیبانی و عبور بقیهٔ ترافیک از VPN، **Bypass selected** را انتخاب کن و همان برنامه را اضافه کن.

### آپدیت و داده‌های قبلی

در **Settings → Automatic updates** آپدیت خودکار را فعال کن؛ همان موقع بررسی انجام می‌شود و در اجراهای بعدی هم ادامه دارد. دانلود باید با `SHA256SUMS` ریلیز مطابقت داشته باشد. پس از نصب، برنامه را دوباره باز کن. در ویندوز نصب روی مسیر قبلی فایل سرورها و ساب‌ها را نگه می‌دارد؛ در لینوکس، استخراج ZIP به‌تنهایی آپدیت نیست و باید نصب‌کننده اجرا شود. پیش از انتشار گزارش خطا، لینک ساب، رمز کانفیگ و فایل‌های runtime را از گزارش حذف کن.

### تست و محدودیت‌ها

ریلیز ویندوز فقط پس از عبور workflow ساخت، نصب Setup، اجرای WebView2، واردکردن/حذف سرور از رابط واقعی، بررسی چیدمان و تست‌های TUN/DNS/HTTPS/بازیابی در Runner ویندوز منتشر می‌شود. نتیجه و تصاویر هر اجرا در [GitHub Actions](https://github.com/Aliazadi-1776/WProxy-v2ray/actions/workflows/windows-release.yml) در دسترس‌اند. این تست‌ها جای آزمایش سرور شخصی، sleep/resume، تغییر شبکه یا تست روی تمام لپ‌تاپ‌ها را نمی‌گیرند؛ پوشش TUN واقعی ویندوز عمدتاً مسیر Xray است و تست فیزیکی sing-box/Mihomo جداگانه لازم است.

رابط Manager روی لینوکس ساخته، نصب و اجرا شده است. تست نشست واقعی همهٔ نسخه‌های KDE/GNOME و همهٔ توزیع‌ها ادعا نمی‌شود. برای Fedora، SELinux را خاموش نکن؛ [راهنمای فارسی رفع مشکل فدورا](https://github.com/Aliazadi-1776/WProxy-v2ray/blob/v2.8.4/docs/FEDORA.fa.md) مسیر تشخیص و بازیابی را توضیح می‌دهد. نسخه‌های Atomic و macOS نصب‌کنندهٔ پشتیبانی‌شده ندارند.

## English

WProxy is a desktop client for your own configuration or subscription. This release introduces the dark-and-lime Tauri Manager and includes the previously developed connection/recovery improvements since 2.8.3. The UI redesign retains the existing core implementations and native connection bridge.

- **Windows 10/11 x64:** download **WProxy-2.8.4-Setup.exe** and verify its hash. The installer includes the app, pinned sing-box/Xray/Mihomo runtimes and Wintun. Separate Python/core installation is unnecessary. Windows requests UAC for system TUN changes.
- **Linux:** download **WProxy-2.8.4-GitHub.zip**, install your distro dependencies from README, then run `bash scripts/install.sh --desktop gnome`, `--desktop kde` or `--desktop none`. The `.plasmoid` asset is the KDE widget and requires the installed backend.
- Add a subscription under **Subscriptions**, or a link/native JSON/YAML/file under **Servers → Add server**. Use the Dashboard dial / **Quick connect** for HTTPS-checked automatic selection, or Connect/Switch beside a specific server. Disconnect from the connected Dashboard dial or server details.
- The Manager adds measured traffic/session cards, source/engine filters, sorting, favorites, list/grid views, subscription metadata, application selection, themes, reduced motion and **Ctrl+K** search. Browser development previews contain illustrative data and cannot establish a VPN connection.
- **Routing:** All traffic uses the VPN; Only selected tunnels listed apps/sites; Bypass selected keeps listed traffic direct. Pick real applications from the installed/running list or browse an executable. Linux applies changes through the existing active-tunnel path; Windows changes apply after reconnecting.
- **Settings → Automatic updates** checks immediately when enabled and again on later launches; downloaded updates must match the release checksum manifest. Reopen after installation. Saved Windows profiles remain in the per-user store.
- Windows release publication is gated on installed WebView2 UI/bridge tests and native TUN, DNS, HTTPS and rollback checks in GitHub Actions. Coverage primarily exercises Xray; physical sing-box/Mihomo Windows TUN, every desktop/distribution, sleep/resume and users' remote servers are not universally verified.

See the [English README](https://github.com/Aliazadi-1776/WProxy-v2ray/blob/v2.8.4/README.md), [Windows guide](https://github.com/Aliazadi-1776/WProxy-v2ray/blob/v2.8.4/docs/WINDOWS.md) and [Fedora recovery guide](https://github.com/Aliazadi-1776/WProxy-v2ray/blob/v2.8.4/docs/FEDORA.md). Live TCP latency is not end-to-end VPN verification; test the sites you need in an application that is actually routed through the tunnel.
